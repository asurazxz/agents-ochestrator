# Accepted decisions

Only explicit human choices belong here. Recommendations and agent proposals belong in design documents or proposal records.

## D001 — Prioritize shared context and decisions

- Date: 2026-10-06
- Status: Accepted
- Approved by: Project owner, in the initial planning conversation
- Decision: The initial product priority is shared context and decisions across teammates.
- Rationale: This addresses repeated onboarding and inconsistent outputs across devices and sessions.

## D002 — Review updates before sharing as approved context

- Date: 2026-10-06
- Status: Accepted
- Approved by: Project owner, in the initial planning conversation
- Decision: Agents propose updates; a teammate approves or edits them before they become approved project context.
- Rationale: The team controls what counts as agreed knowledge.

## D003 — Start with Codex and Claude Code

- Date: 2026-10-06
- Status: Accepted
- Approved by: Project owner, in the initial planning conversation
- Decision: Codex and Claude Code are the first intended integrations, using MCP for shared context capabilities.
- Rationale: Teammates retain their own coding tools and devices.
- Limit: Exact client versions and automation behavior need validation.

## D004 — Hosted workspace with invitations

- Date: 2026-10-06
- Status: Accepted
- Approved by: Project owner, in the initial planning conversation
- Decision: Use a hosted workspace that teammates join through invitations.
- Rationale: Availability should not depend on one teammate keeping a laptop online.

## D005 — Any member may approve

- Date: 2026-10-06
- Status: Accepted
- Approved by: Project owner, in the initial planning conversation
- Decision: Any project member may approve or edit a proposal, including proposals from their own agent. Record who approved each change.
- Rationale: Keep review practical for small teams while preserving attribution.

## D006 — Fully open-source and self-hostable distribution

- Date: 2026-10-06
- Status: Accepted
- Approved by: Project owner, in product planning and the documentation update request
- Decision: Target fully open-source distribution and easy self-hosting. Keep recurring costs as low as practical.
- Rationale: Small teams should be able to run the product on infrastructure they control.
- Limit: The specific license is unselected. Operating hardware, domains, and optional inference may still cost money.

## D007 — Initial testing through existing Twingate access

- Date: 2026-10-06
- Status: Accepted
- Approved by: Project owner, in the hosting discussion
- Decision: Initially test using a laptop and desktop with a shared server reachable through the existing Twingate private network.
- Rationale: Validate cross-device behavior before introducing public hosting.
- Limit: No network configuration or connectivity has been changed or verified by this project.
